# Codex Job Hunting Agent

模式 B 的本地求职工作台：手动导入 JD、真实事实库、来源溯源、批量词项匹配，以及经明确授权的官方 ATS API 采集。可组装日英事实原文草稿，审阅批准后导出文本；不会调用模型改写、填写或投递。

**当前没有配置具体公司或招聘源。** LinkedIn/OpenWork 只允许手动导入。
- 匹配 JD：LinkedIn = OpenWork > 官方，报告显示实际来源。
- 官方核验及申请入口：官方优先。
- “采集已授权来源并匹配”仅在用户点击后运行，没有持续后台任务。

本次变更、权限边界及未实现项：[Phase 2 实施说明](docs/Phase2实施说明.md)。

完整中文方案：[docs/技术方案.md](docs/技术方案.md)。六个后续逻辑 Agent Prompt 在 prompts/，当前并未调用模型。原始方案中的 Phase 1 描述为历史版本，当前能力以 Phase 2 说明为准。

## 运行
在本项目目录内执行：
```sh
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -e '.[test]'
python3 -m streamlit run app.py --server.address 127.0.0.1
```
浏览器打开本地显示的地址，通常为 http://127.0.0.1:8501。数据首次运行时自动迁移到 data/jobs.sqlite3，不进入 Git。不要公开此服务。

## 使用
1. 手动粘贴 JD，填写来源链接、公司、岗位、地点。只有核对过的企业岗位编号才填写。
2. 在事实库添加真实日语或英语原文和证据位置；明确核实后勾选确认。
3. 在岗位页面查看优先 JD、全部来源及可能重复项，计算词项覆盖。

事实库初始为空，没有读取父目录简历。事实证据路径只作为文本保存。测试数据只存在临时目录，不代表用户经历。
相同公司加企业岗位编号或申请链接才跨来源自动合并；名称相似只提示。现已支持人工核对合并、撤销合并和标记不同岗位；支持事实确认/撤销，以及已批准草稿的文本和证据清单导出；事实正文修改和批量数据导出尚未实现。API 记录包含读取授权与刷新批次。
来源官方归属须用户核对；URL 校验不等于归属验证。匹配忽略未确认事实，只覆盖少量明确词项，不评估语言等级、年限或录用概率。

## 测试
```sh
python3 -m pytest -q
```
标准库核心、来源适配器、采集管线测试和 Streamlit AppTest 均不访问真实网站。依赖版本范围在 pyproject.toml；未建立生产锁文件。

```sh
/opt/anaconda3/bin/python3 -m streamlit run app.py --server.address 127.0.0.1
```
验收记录见 docs/验收记录.md。

## 人工核对跨来源岗位
在界面底部展开“人工核对跨来源岗位”，选择待核对岗位和保留的主岗位，对照两边已保存的 JD，填写依据并明确确认。可合并来源或标记为不同岗位；合并可以撤销。详细边界见 [人工核对说明](docs/岗位核对说明.md)。

## 日英简历草稿（Phase 3 基础）
在“日英简历草稿与审阅”选择岗位、语言和已确认事实；也可按 JD 词项自动筛选排列事实。当前只组装事实原文，不翻译、不润色、不补全经历。
逐条审阅事实与证据后批准，下载 TXT 和溯源 JSON。JD、事实库、来源状态或分组变化会使旧版失效；需要重新生成和批准。
在“确认或撤销事实状态”可以确认待确认事实或撤销确认。详细边界见 [Phase 3 实施说明](docs/Phase3实施说明.md)。

## 申请准备工作台（Phase 4 基础）
展开“申请准备与手动提交记录”，选有效的已批准简历，按需引用事实准备字段。核对入口、简历、字段和实际网站问题后，可下载包含简历及证据的本地 JSON 准备包。
网站由你自行打开、填写和最终提交；系统只记录你明确报告的结果。事实/JD/入口变化后，旧准备记录不能继续作为当前清单导出。
详见 [申请准备说明](docs/Phase4申请准备说明.md)。本次没有加入实际网页自动填写。
