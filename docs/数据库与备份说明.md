# 本地数据库、备份与恢复

更新日期：2026-11-04。

## 当前实际状态

项目已经使用 SQLite，不需要另外安装数据库服务器、开云账号或提供数据库密码。

本次已初始化 `data/jobs.sqlite3`，表结构为 migrations 1–7。初始化验收时岗位、事实、简历、申请等业务记录均为 0；没有导入任何私人履历或虚构数据。首份本地备份已创建并通过校验。后续使用后这些计数会自然改变。

数据库及备份都被 Git 忽略，不上传 GitHub。源码仓库仍保存建表迁移和测试，以便在新机器创建空库。不能仅靠 GitHub 代码恢复私人数据。

如果后续需要服务器部署、多人访问或 PostgreSQL，会先告知用户并确定部署/权限与费用；本版没有远程 DB 客户端、连接串或云服务。模型 API 按用户选择仍关闭，不读取模型密钥。

## 工作台中的维护功能

展开“本地数据库状态与备份”：

- 显示当前实际数据库文件位置。
- 检查表结构、迁移版本、quick_check、外键一致性及常用表计数。
- 创建一致性备份，写入本机 backups 目录，同时保存时间、版本、大小及 SHA-256 元信息。
- 列出最近 50 份备份并校验；损坏、缺失或摘要不符的备份不能恢复。
- 下载数据库及配套元信息文件，便于用户另行保存在私人位置。
- 从校验通过的备份创建新的 restored 副本，**不覆盖正在使用的数据库**。恢复副本路径会明确显示，工作台仍使用原库。

备份使用 SQLite Online Backup，而非直接复制运行中的主文件；副本创建后检查数据库完整性和外键。参考 [SQLite 官方 Backup 文档](https://www.sqlite.org/backup.html)。quick_check 和 foreign_key_check 是各自独立的检查，参考 [SQLite PRAGMA 文档](https://www.sqlite.org/pragma.html)。

如果当前连接有未完成事务，拒绝备份，避免等待自己的未提交写入。备份等待有 15 秒上限；失败会清理本次产生的不完整文件，已有数据库和重名备份不会被替换或删除。

## 数据位置与切换恢复副本

默认：

```text
data/jobs.sqlite3
data/backups/backup_<UTC时间>_<随机标识>.sqlite3
data/backups/backup_<UTC时间>_<随机标识>.sqlite3.json
data/restored/restored_<UTC时间>_<随机标识>.sqlite3
```

备份文件名与元信息使用明确 UTC 时间和唯一标识；不存在覆盖旧备份的“最新文件”策略。没有自动删除备份或历史记录。

切换到恢复副本需要停止当前工作台后，明确设置 `JOB_AGENT_DB_PATH` 为界面显示的完整绝对路径，再启动。该变量只接受 `.sqlite3`、`.sqlite` 或 `.db` 扩展名，本地文件模式；不接受 PostgreSQL URL 等连接串。默认未设置时继续使用原库。

例如（先把示例路径替换成界面生成的实际副本路径）：

```sh
JOB_AGENT_DB_PATH='/绝对路径/restored_实际文件名.sqlite3' \
/opt/anaconda3/bin/python3 -m streamlit run app.py --server.address 127.0.0.1
```

显式传入 connect(path) 的程序调用优先于环境变量，方便测试与开发。恢复副本若版本较旧，打开时会先备份该副本再升级，不改原库。切换期间不要同时用多个工作台分别修改不同副本，以免自行造成版本分叉。

当前界面只读取本机受管理备份目录，不提供任意 SQLite 文件上传或直接覆盖原库。下载后若要迁移到另一台机器，需要同时保管备份与 `.json` 元信息；本版没有自动的远端导入/同步功能。

## 升级保护

连接时先核对迁移版本是否为当前代码支持的连续前缀及基本表/关键列是否齐全。未知未来版本、断号、非项目数据库或缺失结构会停止，不尝试自动修补、降级或覆盖。

已存在且需要升级的库，必须先成功生成一致性备份；备份失败则不运行迁移。各迁移脚本按自身事务执行；某一步失败时回滚该步、关闭连接并保留升级前备份。此前已成功完成的迁移可能已经提交，整个多步升级不是单一事务。

当前版本再次打开不重复生成备份。新空库直接初始化，不创建无意义的升级前空备份；本次首份备份是在初始化检查后主动创建。

## 安全边界

- 新建数据库、副本和备份文件使用 0600，新增维护目录使用 0700；不擅自修改既有目录权限。符号链接文件及直接的维护目录链接会被拒绝。
- 本地数据库与备份没有应用级加密。备份包含全部个人事实、JD、申请和上下文快照；应私人保存，系统磁盘保护另行配置。
- 摘要用于检出意外修改，不是数字签名。能同时修改数据库和元信息的人可能伪造摘要；不把不明来源数据库当作受信任输入。
- 状态检查不证明业务事实真实，也不证明外部岗位仍开放。
- 没有自动远程备份、数据保留期限、备份清理、实时多设备同步或 PostgreSQL 迁移。
