# 当前项目说明

核对日期：2026-11-27。版本：0.9.0。本文件与 README 描述当前状态；历史技术方案不代表功能全部实现。

## 项目目的与组成

支持岗位查找与比较、日英简历轻量修改和申请准备，最终由用户确认并自行投递。代码主要借助 Codex 生成和修改。

项目目前由两部分配合使用：

1. 单独配置的 Codex 定时任务：已执行自动搜索、官方 JD 条件核查、第二新卒岗位筛选和历史推荐记录。任务配置、个人背景和结果不在本仓库。它使用 Codex 环境能力，不是本 Python 应用内置的搜索服务。
2. 本仓库的本地应用：保存 JD、来源和快照，管理真实事实、重复关系、偏好排序、简历修改建议和申请准备。模型 API 关闭。

两者尚未自动联动。当前应用不能直接同步聊天、读取定时任务结果或自行每日通知。已有手动 CSV/JSON 导入可用于整理后接收数据，但现有推荐摘要不等于完整 JD，仍需核对字段和正文。

## 已实现的应用功能

| 范围 | 当前行为与限制 |
| --- | --- |
| 导入与来源 | 粘贴或手动 CSV/JSON 导入；保留 job_source_links 及 JD 快照；一批最多50条、1MiB，预演后确认保存，失败回滚。 |
| 去重 | 同公司加同岗位编号或申请链接按强证据归并；弱相似提示人工确认；允许人工合并、撤销和标记不同。不能保证识别全部重复。 |
| 匹配与排序 | 少量固定词项和用户偏好的字面比较，可解释来源与依据；不理解所有否定、年限和等级，不是资格认定或录用概率。 |
| 官方 API | Greenhouse/Lever/Ashby 固定只读接口，需逐来源权限；没有预置公司；用户点击才运行。 |
| 简历小改 | 原文、理由、替换文本、JD引用、事实依据、差异及审阅记录；默认保留结构；不改 PDF/Word，不写回原文。 |
| 自动措辞 | 仅保守规则提示和行尾空白处理；专业自然语言改写未自动运行。 |
| 辅助草稿 | 根据已确认日英事实原文选择、排序、组装，审阅批准后导出；不翻译、不编造事实。 |
| 申请准备 | 本地核对清单、材料导出与用户自报；不填写网站、不提交、不联系招聘方。 |
| 数据库 | 本地 SQLite，9个迁移版本；已有库升级前备份，恢复创建独立副本；不使用云数据库。 |
| 语义接口准备 | 离线请求格式和引用验证，真实模型调用被禁用，不读密钥。 |

## 架构与数据流

Streamlit 展示与操作 → Python 业务模块 → SQLite。导入、审阅及准备记录保持可追溯。数据变化会使旧匹配上下文、简历批准或建议失效，不能把旧结果默认为当前有效。

主要表包括 jobs、job_source_links、jd_snapshots、facts、匹配报告、来源权限、人工去重关系、简历版本与引用、申请准备记录、偏好与排序版本、离线语义记录、批量导入记录、resume_passages、resume_edit_suggestions。具体字段以 migrations/001–009 SQL 为准。

prompts/ 的6个角色用于设计约束，不是已经启用的多模型Agent系统。无独立后端服务器、后台队列或向量数据库。

## 隐私与运行边界

个人资料、原始简历、推荐内容、定时任务配置、数据库和备份留在私有环境。公开材料只描述通用能力，不包含个人岗位匹配档案。应用仅本机运行，不提供公开访问认证。

LinkedIn/OpenWork只允许手动导入；不加入未经授权的抓取、浏览器操作或凭证导出。其他来源按权限使用；固定API代码存在不代表已对实际公司启动采集。模型API仍关闭，未来启用前另行告知。
