# Phase 4 基础：本地申请准备工作台

更新日期：2026-11-04。

本次实现是本地准备、清单导出和人工结果记录，不是网站表单自动填写。未新增浏览器操作或申请写入能力，未配置公司或进行真实投递。

## 已实现流程

1. 选取当前有效且已批准的日/英语简历，预览原文。
2. 可选地为姓名、邮箱、电话、经历/自我介绍、学历及语言能力字段选择已确认事实。字段值只拼接对应语言的事实原文，保留事实 ID、revision 和证据。不得在准备阶段直接补写未经确认的答案。
3. 列出尚待本人回答的问题。问题未清空前不能完成本地核对；核实后需创建新的准备记录，旧记录保留。
4. 申请入口从已保存来源的 application_url 选择：官方优先，其次 LinkedIn/OpenWork，同级取最近观察。API 来源全部标记缺席时不使用该来源的入口。不会猜测链接，也不会把 JD 详情链接自动当作申请链接。
5. 用户明确核对入口与岗位、简历、字段、实际网站问题，准备记录进入等待用户自行提交状态。四个本地核对项不是网站法律声明，也不代表已替用户勾选任何条款。
6. 导出 JSON 准备包：包含简历全文、简历事实溯源、字段原文及引用、入口和校验摘要。导出不向招聘网站发送数据。
7. 用户自行在网站完成申请后，明确选择“记录我已自行提交”。系统只记录用户自报、备注和记录时间；未独立核验，时间为记录时间，不是网站确证的投递时间。

未列入清单的实际表单字段、资格判断、隐私条款、同意声明和验证码都由用户自己完成。没有网站字段发现或完整性验证。字段名与事实内容是否语义适配也需要用户核对，例如一段经历不会自动变成姓名或邮箱。

## 状态机

```text
prepared -> awaiting_user_submit -> user_reported_submitted
    |               |
    +-----> needs_review
    |               |
    +-----> abandoned <----+
```

- prepared：本地待核对；不是已填写。
- awaiting_user_submit：本地核对完成；不是投递成功。
- needs_review：当前引用失效，需重新批准简历并创建新准备记录，不能直接恢复旧记录。
- user_reported_submitted：不可改写的用户自报历史；后续上下文失效只提示，不把历史改成“从未提交”。
- abandoned：用户明确放弃的本地记录；不意味着撤回已发送给企业的任何申请。

进入等待用户提交必须有已登记申请入口，无待回答问题，并明确完成全部核对项。只有该状态可导出准备包或记录用户自报结果。重复提交记录操作被拒绝。

## 版本和失效

准备包绑定 job_id、resume_id、批准摘要、正文摘要、上下文摘要、字段原文和证据、入口来源。预览后完成核对还要核验 payload_hash。

展示、核对、导出和自报前重新校验；JD、事实、来源或申请入口变化会使未结束记录进入 needs_review。简历采用保守失效策略，无关事实新增或相同 JD 再次观察也可能要求重新准备。

已自报提交或已放弃的记录保留历史状态；当关联内容失效时显示 currently_valid=false，不能再作为当前准备包导出。已经下载的文件不能撤回。已实际提交但随后资料变化的情况，应保留备注和历史，本版本不能在失效记录上补报过去提交，需要后续单独的历史登记流程。

## 数据与模块

005_applications.sql 新增 applications 和 application_events，版本升级保留此前岗位、来源、事实和简历。

- applications：引用岗位/简历、不可编辑准备包、摘要、状态、本地核对摘要和用户自报记录时间。
- application_events：每次操作的 application_id、事件、user/system 行为者、备注和记录时间。
- applications.py：纯本地服务，使用事务及锁内状态复核，不提供网络、浏览器、点击、填表、文件上传或申请 POST。

多条准备记录不代表多次真实投递，系统不自动去重用户在外部网站的提交。摘要用于一致性校验，不是数字签名。直接控制数据库者仍可篡改数据。

个人资料、证据和下载清单只保留在本地数据库/用户下载中，不进入 Git。请不要在提交备注中填密码、令牌或网站凭证。
