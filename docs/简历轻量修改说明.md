# 简历轻量修改：建议和文本，与岗位匹配并重

更新日期：2026-11-05。

## 最新产品范围

Agent 应同时服务“找岗位、匹配”和“按 JD 微调现有简历”。简历交付改为轻量建议和可复制文本：保留原有结构、主要表达和事实，不默认重写。

不修改或重排 PDF/Word，不以生成完整新文件为目标。之前路线图中的正式 DOCX/PDF 模板、自动重排不再是当前交付要求，除非用户另行提出。

## 工作流

1. 进入主界面独立页签“简历轻量修改”。
2. 选择目标岗位及原文语言，粘贴一条 bullet 或一小段现有原文，填写位置说明。无需上传简历 PDF。
3. 选取支撑这段经历的已确认事实，明确锁定姓名、公司、职称、学历、日期和语言等级等词项。数字会自动检查，但程序不能识别所有实体。
4. 查看保守规则建议及 JD 词项/证据缺口。原句合适时保留原文，不为了显得“改过”而改。
5. 若有措辞小改，将替换文案、修改理由和对应 JD 逐字引用录入，保存为待审阅建议。
6. 对照原文/替换文本/差异/事实依据，用户明确采纳或不采纳。采纳只是记录文字建议的决定，不自动应用到任何文件。
7. 可下载 TXT，包括原文、修改理由、替换文本、JD 引用和事实依据。用户自行粘贴到自己的简历编辑工具。

事实素材草稿功能保留为辅助功能，不作为重新生成整份简历的默认路径。采纳建议不直接修改事实库或此前批准的草稿；如用户要把新表达保存为素材，需要另行核实和登记。

## 当前自动能力与限制

模型 API 仍关闭。规则引擎目前只能：
- 清理行尾多余空格，保留缩进、项目符号和行序。
- 提示有限词表中已涉及的 JD 能力和缺少证据的关键词。
- 没有可靠的小改时明确保留原文，给出缺口建议。

当前不自动生成专业的自然语言润色。措辞替换可以由用户手动输入或将另行获得的建议粘贴进来再核对；未来接入模型时复用离线小改说明与同样的审阅边界。真正启用 API 前仍先告知用户，不读密钥、不外发文本。

## 小改检查

- 单次最多 3000 字符、8 条非空行，只收用户提供的短段落。
- 替换须有已确认、对应语言的事实引用和逐字 JD 动机引用。
- 字符相似度低于 70%、扩写超过保守长度范围、改变非空行数/缩进/项目符号结构时拒绝。
- 对数值、日期/等级内数字做规范化后的出现次数检查；用户锁定词必须逐字保留相同出现次数。
- 新增常见职责强化词（如 supported→led、managed、主導）或原文及所选事实均不支持的已知技能词时拒绝。
- 不允许未修改的句子伪装成“替换建议”；直接保留即可。

**以上是形式保护，不是语义正确性证明。** 相似度高也可能改变意思；“two→three”等文字数值、未锁定的公司/学历、词表外技能、职责互换仍可能无法识别。用户必须确认事实、语气和责任边界；不能把“检查通过”描述为已证明真实。

## 数据与版本

新增 009_light_edits.sql：resume_passages 保存原文、锁定词、选定事实快照、目标岗位和上下文摘要；resume_edit_suggestions 保存替换文本、理由、JD 引用、来源、摘要及审阅状态。

状态：review_required → accepted / rejected；JD、事实或来源等上下文变化后为 obsolete。已过期建议不能作为当前替换文本导出。历史原文不覆盖，建议不反写事实。

离线 editing_brief 只包含原文、目标 JD、锁定词和选定事实文字，不自动加入证据路径；它仍可能含个人信息，应私人保存。没有原文件路径输入、PDF 读取/编辑模块、文件写回或网络调用。

本次沿用现有 SQLite 新增两张表。正式库升级前自动备份，不增加服务器 DB、账号或费用。用户简历片段和建议留在本地数据库，不上传 GitHub。
