# Phase 3 基础：事实引用、日英草稿与审阅

更新日期：2026-11-04。

## 本次交付
本地确定性流程：选择目标岗位及日/英语 → 筛选或手动选择已确认事实 → 按顺序组装原文 → 审阅全文及逐条证据 → 用户明确批准 → 下载 TXT 与溯源 JSON。

两种组装方式：
- 手动选择：按用户选择顺序保留事实原文。
- JD 规则筛选：只使用现有有限词表，按事实覆盖的 JD 词项数降序排列；并列按事实 ID。找不到对应语言的已确认词项事实时拒绝自动生成，用户可补充事实或手动选择。

没有模型调用、自动翻译、改写或新增技能/经历。缺少对应语言原文直接报错，不以另一语言替代。用户确认表示用户已核实，不代表系统独立证明经历真实。规则筛选不能判断否定、熟练度、等级或年限。

## 数据模型
迁移 004_resumes.sql 新增：
- facts.revision：确认状态每变更一次增加版本号。
- resume_versions：岗位、语言、正文、正文摘要、上下文快照及摘要、状态、批准摘要及时间。
- resume_claims：草稿内顺序、原文、事实 ID 及当时证据，逐条可追溯。

草稿正文和引用不提供修改 API；重新选择/排序生成新版本。历史草稿保留。事实确认/撤销不改正文，保留旧版本上下文快照。

## 状态与批准
状态为 review_required → approved；任何需要重新审阅的变化进入 obsolete，失效版本不能再次批准，必须生成新版本。

批准绑定：版本 ID、正文摘要及上下文摘要。上下文包含目标岗位身份、全事实库及版本、匹配 JD、来源链接和最后观察时间、来源可用状态等。匹配仍优先 LinkedIn/OpenWork 手动导入 JD，缺失才回退官方。

显示、批准和导出时校验上下文及正文引用；不在后台持续扫描。采用保守失效：新增无关事实、相同 JD 再次刷新、API 缓存刷新产生新批次等也可能要求重新审阅。事实撤销后再确认会增加 revision，即使确认状态回到原值，旧批准也不会恢复。

合并/撤销合并会改变来源归属或观察上下文；旧版不继续导出。岗位失效、拒绝或被合并隐藏也阻止批准。

摘要用于一致性检查，不是数字签名。能直接修改数据库及重新计算全部摘要的人仍可改写内容，不能宣称防恶意篡改。已经下载的文件无法撤回；下载前检查不能替代用户提交前复核。

## 界面使用
1. 导入 JD，添加真实事实及证据；事实必须明确确认。
2. 事实须有目标语言原文；系统不会凭空翻译。
3. 展开“日英简历草稿与审阅”，选择岗位和语言，手动选事实或使用 JD 词项筛选。
4. 查看版本正文及事实 ID/证据，明确勾选已审阅后批准。
5. 下载已批准的文本，按需下载含个人证据位置的 JSON；注意私人保存。
6. “确认或撤销事实状态”用于确认待确认事实或撤销已确认事实。事实正文错误时撤销旧事实，再添加正确事实并核实；没有就地正文编辑。

## 边界与后续
这只是 Phase 3 的事实与审阅基础。导出是经历/实绩原文片段集合，不是完整履歴書、正式職務経歴書或英语 resume 的最终排版。没有自动姓名、联系信息、教育分区或格式补全。
尚未实现：模型微调、差异对比编辑、DOCX/PDF 模板、完整事实正文修订历史、LLM 语义核验或申请表填写。不会调用模型处理私人事实，也不会提交申请。
日英两种原文都必须用户确认，系统不独立验证两种语言语义等价。草稿及上下文快照含个人资料，数据库及导出不得上传 GitHub。
