# 手动批量导入 JD

更新日期：2026-11-05。

## 用途与边界

将用户自己整理的官方、LinkedIn、OpenWork 岗位一次性导入本地工作台。此模块不访问 URL、不抓取网站、不读取浏览器，也不调用模型。LinkedIn/OpenWork 的自动化限制和现有来源优先级不变。

导入的只是岗位及 JD，不是用户能力；不会创建、确认或修改任何简历事实。真实资料和导入预览保存在本地数据库，不进入 Git。

## 输入方式

- 粘贴严格 JSON 数组或 CSV 文本。
- 上传 UTF-8 的 `.json` / `.csv` 文件，上方选择的格式必须与扩展名一致。
- CSV 模板可直接下载，只有表头，没有示例岗位或虚构经历。

每批 1–50 条，原始及规范化后的数据均不超过 1 MiB。每条 JD 不能超过 20 万字符；公司、标题、地点各限 500 字符，企业岗位编号 200 字符，链接规范化前后均限 4000 字符。CSV 还受 Python 标准库单字段大小限制，过长 JD 请减少长度或改用 JSON。

不猜测 Shift-JIS、UTF-16 等编码，不用替代字符掩盖乱码；有编码错误时要求用户先另存为 UTF-8。

## 字段

| 字段 | 必填 | 含义 |
|---|---|---|
| company | 是 | 公司名称 |
| title | 是 | 岗位名称 |
| location | 是 | 地点；未给出时由用户明确填“未注明” |
| source | 是 | official / linkedin / openwork |
| url | 是 | 来源 HTTPS 链接 |
| jd | 是 | 手动获得的完整 JD 正文 |
| application_url | 否 | 已核对的申请链接，不会据此发起申请 |
| requisition_id | 否 | 企业岗位编号；不要把平台列表 ID 当作企业编号 |

每个值都必须是文本；未知列、缺失值、重复 JSON 字段、重复 CSV 列及多余单元格会拒绝。CSV 含逗号、引号、换行的 JD 必须正确加引号。系统不执行输入中的公式或指令；模板导出不包含用户内容。

## 预览与提交

1. 校验整批输入并规范化 URL。
2. 使用 SQLite 在线备份到内存副本，在副本中模拟实际导入；正式岗位、来源、JD 和事实不变。预览本身及输入会保存在本地 batch_imports，便于后续确认和追溯。
3. 展示每条记录的目标岗位、来源链接、操作、潜在重复编号及警告。预览中的新编号不是已建立记录。
4. 用户逐条核对、明确勾选确认后，提交绑定预览摘要。
5. 锁内再次核对底层岗位/来源/快照及人工核对关系指纹，执行后比较实际效果与预览；不一致或任何一条失败都回滚整批岗位变更及相关审计事件。

操作分类：
- new_job：新增独立岗位。
- attach_source：按同公司及企业岗位编号或同申请链接，将来源归并到已有岗位，必须核对是否确为同岗。
- new_jd_snapshot：已知来源出现新正文，保留历史快照。
- reuse_jd_snapshot：来源恢复为曾出现的旧正文，切换当前版本而不重复存正文。
- refresh_existing：已有正文再次观察，可能同时更新该来源的申请链接。
- skip_duplicate_in_batch：同批规范化后内容完全相同，只处理首次出现。

同批同链接却有不同内容时，整批拒绝，要求用户明确保留哪版，不通过行顺序偷偷覆盖。公司/标题/地点相似而无强证据时仍保留为独立岗位，提示人工复核。

## 公司与元数据保护

已知 URL 对应的公司不同，会拒绝改写归属。例外只针对该链接经过用户人工核对的当前合并关系：允许用原来源公司别名刷新，并明确提示主岗位公司名称不同。此例外不会授权其他链接、其他岗位或全局别名匹配。

首次保存的岗位标题、地点和企业编号不自动覆盖；输入不同会提示保留原记录。更新申请链接会单独警告。既有规则仍可能把共用的企业申请入口当作强证据，用户必须在预览中复核归并目标；本版没有语义去重或自动修正功能。

## 版本与失效

岗位、来源、JD 快照、合并或不同岗位判断变化，会使未提交预览过期；需要重做。事实库的独立变动不影响导入效果，因此不单独使导入预览失效。

已提交批次不能重放，报告作为历史保留，不声称是岗位的实时状态。可另建新批次刷新同一来源；即使 JD 一字未变，也会更新来源观察时间，因此既有简历批准或申请准备可能要求重新核对。

摘要只用于一致性检查，不是数字签名。预览记录没有自动清理策略，批次多时数据库会增大，之后应设计保留/清理功能。

## 数据库与本次状态

新增 008_batch_imports.sql，沿用现有本地 SQLite，不需新建远端 DB 或账号。既有库升级前由数据库维护模块自动备份。

正式本地数据库已安全升级到第 8 版，健康检查通过；升级验收时岗位、事实和批次仍均为 0，没有将测试数据写入正式库。
