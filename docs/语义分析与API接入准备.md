# 语义分析与 API 接入准备（离线）

更新日期：2026-11-04。用户选择：先完成代码，暂不启用模型 API。

## 本次实际交付

- semantic.py 提供独立的分析输入/输出协议、提示词版本、离线请求预览、手动 JSON 结果导入、逐字引用校验、人工审阅和过期判断。
- 没有 HTTP 传输模块、SDK 依赖、密钥读取或后台模型调用。invoke_api 始终拒绝；界面明确显示模型 API 未启用。
- make_responses_payload 只是未来 OpenAI Responses 请求的纯序列化函数，没有连接 OpenAI，也未选定真实模型或验证账号可用性。通用分析结果格式可供之后适配其他服务。
- 现有规则匹配与经授权的 ATS 读取仍按原权限工作；“模型 API 关闭”不撤销用户已有 ATS 读取权限。

## 预览流程

选择已导入的岗位 → 明确选择最多 20 条已确认事实（默认不选）→ 生成离线预览。未选择事实时只准备 JD 分析。

未来分析输入仅包含 JD 和所选事实的 fact_id、日语/英语原文。不会自动添加证据路径、申请链接、公司元数据、未选事实或任何密钥。原文中仍可能包含个人信息，不保证自动匿名化；用户必须检查原文。完整预览可下载到本地，不会发送。

本地另存 job_id、source_link_id 和 JD 摘要用于溯源；这些 local_provenance 字段不会被请求序列化函数加入模型输入。

JD 不超过 3 万字符，预览数据不超过 256 KiB，不静默截断。需要更长上下文时应另行设计分段和引用范围，不在本版猜测补全。

## 分析结果协议

根字段只允许 requirements 和 questions。每条要求包含：

| 字段 | 意义 |
|---|---|
| requirement | 分析者对要求的描述，仍需人工核对 |
| jd_quote | 请求中 JD 的逐字片段 |
| importance | required / preferred / unknown |
| relation | evidence_candidate / unknown / conflict_candidate |
| fact_quotes | 引用的 fact_id 及逐字事实片段 |

unknown 关系必须没有事实引用，其他关系必须有引用。最多 50 条要求和 50 个待核实问题；禁止额外字段、总分、录用概率或简历正文。每条事实引用只能来自这次明确选中的已确认事实，不能引用事实库中未发送的其他记录。

导入时要求严格 JSON，不自动剥离 Markdown 围栏，不接受重复键、NaN 或无限数字。结果上限 256 KiB。失败不保存部分结果。

**引用校验只能证明片段确实存在，不能证明推理成立。** 例如技能名命中不证明年限/熟练度满足，带否定的句子也可能被误解。requirement 描述、importance 和 relation 都需用户核对；字段名称中的 candidate 不代表已满足岗位资格。空 requirements 也不代表合格或不合格。

结果来源固定记录 manual_import，不假装已经运行模型 API。界面提供审阅或拒绝并记录备注。审阅结果是参考意见，不能替代简历批准；本版不会将它自动写入事实、简历、偏好排序或申请字段。

## 版本与历史

007_semantic.sql 创建 semantic_requests 和 semantic_reports。请求保存输入、摘要、提示词版本、本地来源溯源及上下文摘要；结果保存 JSON、摘要、手动来源和审阅状态。

请求使用既有简历上下文生成摘要，包含 JD、全事实库、来源关系/观察及可用状态等，因此采用保守过期判断。新增无关事实也可能要求重新准备。输入变化后拒绝导入结果，已有结果进入 obsolete。摘要不一致也要求重新计算；摘要不是数字签名。

## 后续真正接入 API 时需要什么

1. 用户确定服务商、具体模型、付费账号与预算；本版没有替用户做选择。
2. 单独实现并测试固定服务端点、超时、限流、拒答/截断处理及结果封装解析。当前不接受任意 base_url，也没有可直接启用的网络开关。
3. 密钥由用户在本机安全配置，不在聊天中发送、不写数据库、不提交 Git。没有读取密钥的现有功能。
4. 增加逐次发送确认并绑定当前输入摘要；调用前重新检查来源/事实版本及发送预览，不能用旧预览绕过核对。
5. 明确告知会发送的原文、服务方数据处理政策和实际费用，再启用；继续禁用工具调用、浏览器操作和真实申请提交。
6. 用少量经用户授权的非敏感材料做真实连通验证，之后才启用实际业务。当前测试均为离线，不代表真实 API 已联调。

## 官方文档依据

使用 OpenAI Docs 核对了未来序列化格式，参考日期 2026-11-04：
- [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)：Responses 使用 text.format 的 JSON Schema；本地 schema 设置 strict 和 additionalProperties=false。
- [Data controls](https://developers.openai.com/api/docs/guides/your-data)：未来序列化请求设置 store=false；该字段不能被描述为保证零数据保留或替代服务的数据控制政策。启用时仍须重新核对。

本版不默认指定任何真实模型；测试使用 fixture-model 作为纯字符串，不是模型推荐。max_output_tokens=4000 是未来请求的输出上限参数，不是费用保证或账号限额。
