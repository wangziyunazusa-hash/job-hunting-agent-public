# 跨来源岗位人工核对

更新日期：2026-11-04。未配置具体公司、未进行真实采集或投递。

## 使用
1. 手动导入 LinkedIn/OpenWork JD，或导入/授权读取官方 JD。
2. 在“人工核对跨来源岗位”选择两条记录，比较已保存的 JD、地点、岗位编号、公司与申请链接。选择“保留的主岗位”时，它的标题、公司与地点将继续作为展示信息。
3. 确认同一岗位后填写核对依据并勾选确认，保存合并。仅来源关系改到主岗位；原始岗位记录、快照、API 刷新记录和历史报告保留。
4. 不是同一岗位时选择“不同岗位”，系统持久保存该对记录的判断，不再显示该对弱证据重复提示。
5. 合并记录下可撤销。只恢复这次合并前属于来源岗位的链接；后来新导入到主岗位的链接留在主岗位。历史报告仍属于生成时的岗位，不会被改写，应重新计算当前匹配。

## 规则
- 合并不会提高来源信任等级。匹配仍为 LinkedIn = OpenWork 优先；官方参考与申请入口仍优先官方。
- 弱证据只提示、不自动合并；人工核对支持公司别名、跨语言标题等无法自动判断的情况，但未实现公司别名库或语义候选召回。
- 合并过的原记录从岗位列表和批量匹配隐藏，保留 merged_into 关系；相同来源 URL 再次导入跟随当前来源所属岗位。
- 禁止嵌套合并：已有合并成员的组不能再次与其他组或岗位合并，应先撤销。这避免撤销时产生含糊的成员归属。
- 撤销前检查来源关系，已变化时整次撤销取消，避免误移动记录。
- 标记不同岗位不覆盖未来新来源的强证据导入规则，也不是全局公司或标题黑名单。
- 数据迁移 003 新增 jobs.merged_into、job_merges 和 duplicate_reviews；事务保证操作原子性，全部使用本地数据库。
- 不增加网络、模型、抓取、填写或提交权限。

## 验证
测试覆盖历史和快照保留、匹配来源优先、批量匹配排除已合并记录、不同岗位判断对称且持久、确认与依据必填、同 URL 再导入、撤销与新增链接、冲突撤销回滚、嵌套合并拒绝，以及完整界面的合并/撤销流程。
